# 百万猜拳演化模拟器

> MILLION-AGENT RPS EVOLUTION SIMULATOR
> 百万级智能体 · 石头剪刀布 · 演化经济 · 实时 3D/WebGL 可视化

一个零依赖（Node.js ≥ 20）的高性能智能体模拟器：最多 **100 万个体**在同一经济体中随机配对猜拳，
带策略基因遗传/突变、繁殖、破产淘汰、天赋、家族谱系、宏观调控、瘟疫与资源有限模式；
前端是原生 WebGL2 + Canvas2D 的实时控制台，通过 **二进制流式快照** 展示百万个体的策略星系、财富分布、
阶层结构与演化趋势。

## 1. 快速开始

无需 `npm install`（零第三方依赖），只需要 Node.js 20+：

```bash
# 默认：100 万人口、端口 8080（初始化约 0.2 秒后自动开始运行）
node src/index.js

# 浏览器打开 http://127.0.0.1:8080
```

常用启动方式：

```bash
node src/index.js --preset standard     # 20 万人口（推荐日常演示，约 47 回合/秒）
node src/index.js --preset demo         # 5 万人口（约 142 回合/秒，最流畅）
node src/index.js --preset million      # 100 万人口（约 9~10 回合/秒）
node src/index.js --preset stress       # 200 万人口（压力测试）
node src/index.js --paused              # 暂停状态启动，等 UI 点「运行」
node src/index.js --port 9000 --host 0.0.0.0
node src/index.js --patch '{"matching":{"mode":"wealth"},"plague":{"enabled":true}}'
```

其它命令：

```bash
npm test              # 运行全部单元/集成测试（零依赖）
npm run check         # 全项目语法检查 + 核心模块导入检查
npm run bench         # 引擎基准测试（默认 100 万人口 × 30 回合）
npm run smoke         # 服务端 HTTP/流式协议端到端冒烟测试（需先启动服务）
npm run web           # 只起静态前端服务（8090 端口），配合浏览器 ?mock=1 演示模式
npm run explore       # 经济/演化动态调参探索（打印阶段统计表）
```

> 前端调试：浏览器打开 `http://127.0.0.1:8080/?mock=1` 可在**不连接后端**的情况下查看完整 UI（本地合成数据）；
> `?selftest=1` 会在页面顶部显示浏览器内自检结果（协议解析 / 面板构建 / WebGL 初始化）。

## 2. 功能与规则

完整规则逐条对照实现说明见 **[docs/RULES.md](docs/RULES.md)**，这里只列要点：

- **个体**：稳定 ID、资产（可负）、负债上限、年龄、累计猜拳/胜/负/平、连胜连败、策略基因、天赋、家族/谱系。
- **匹配**：随机 / 资产相近（对数分桶）/ 策略相近（策略单纯形分桶），每回合全员两两配对，回合末统一结算。
- **结算**：平局各扣成本；胜负时败方扣成本 + 赌注，胜方扣成本并获得赌注；赌注 = 成本 × 倍率 × 风险偏好 × 阶层倾向 × 保守/激进阈值调整。
- **破产**：资产 < −负债上限即破产淘汰，负资产由系统核销（可选：清算给最近 N 个对手）。
- **繁殖**：资产门槛 + 最小年龄 + 一生最多次数 + 双方生育成本；子代继承父母基因（50% 混合 + 突变）、负债上限均值、成本承受力、天赋（可突变）、家族（父系继承）与代数。
- **策略进化**：每 N 次失败微调出拳概率、连败阈值触发策略反转、有概率模仿更高资产对手。
- **阶层/通胀/利息**：四阶层（底层/中层/上层/顶层）与阶层化赌注倾向；成本随通胀因子上涨；负资产每回合计息，超过高利贷阈值利率翻倍。
- **宏观调控（参数 5）**：模式 1 均富、模式 2 高低位再分配、模式 3 随机灾难、模式 4 随机红利、保底补助；均可配置间隔/概率/比例，也支持 UI 手动触发。
- **进阶模式**：瘟疫（感染/流失/抗体/遗传/低资产死亡）、资源有限（系统资金池税收与福利支取）、**公会模式**（默认关闭，可在参数面板开启：成员缴金共担风险、金库兜底/开除、公会等级提供成本折扣、公会团体战与金库转移）。
- **阶层流动**：阶层人数/占比/资产占比 + **上下流动率**（上移/下移/流动率）与各阶层流入/流出实时统计。
- **天赋**：幸运儿（胜率 +1%）、节俭者（成本 −10%）、生育达人（生育成本 −30%）、学习天才（学习速度 +50%）、负债抗性（负债上限 +20%），可遗传+突变。
- **统计观测**：直方图/基尼系数/洛伦兹曲线、人口出生死亡破产率、策略演化、阶层结构、家族 Top 榜、个体一生资产曲线与谱系、时间序列。
- **结束条件（参数 4）**：A 首个资产达阈值 / B N% 个体超阈值 / C 固定回合 / D 存活低于 X% / E 连续 M 回合总资产无增长，另有安全回合上限。
- **平衡性**：新手保护（前 K 回合破产冻结）、连胜惩罚、资产上限软限制（收益递减）、保底补助。

### ⚖ 关于「经济平衡」的重要说明

按需求文档的字面规则实现时：**成本是系统抽水，赌注只在个体之间转移**，
因此胜方的净收益 ≈ 赌注 − 成本 ≈ 0（默认倍率 1.0），整个系统天然通缩 ——
仅靠对局**没有任何个体能长期致富**，繁殖门槛（2000）将永远不可达。

为了让「遗传演化」真正发生，默认配置做了一个**经济平衡设计**（全部可配置/可关闭）：

1. **随机红利（货币投放）**：每 2 回合、50% 概率触发，随机 30% 存活个体各获得 140 元（名义值随通胀指数化）。
   期望收入 ≈ **10.5 元/人/回合**，略高于 10 元/回合的猜拳成本，使人口与经济长期稳定、繁殖门槛可达；
   个体差异来自「谁拿到红利」的随机性 + 风险偏好基因，形成重尾财富分布。
2. **自然死亡遗产继承**：自然死亡的遗产由最多 3 名随机存活者继承（而非蒸发），
   避免人口老龄化阶段货币总量凭空消失导致经济崩溃（规则文档未定义此情形，属守恒设计）。
3. **风险基因初始随机**：每个人的风险偏好 ∈[0.3,2.5]、保守/激进阈值随机，
   使破产淘汰、暴富、风险基因的自然选择都能在观测中真实发生。
4. **保底补助按人口比例**：每回合给最穷的 0.5% 存活个体各 +20（名义值通胀指数化）。

实测（20 万人口、默认配置、600 回合）：存活率稳定在 **~70%~85%**、累计出生 8.5 万、破产 2.7 万、
近似基尼 0.33~0.39、最高资产从 3000+ 增长到 6000+，可稳定长期运行。
若想体验**纯通缩经济**，把参数面板中的「随机红利」关掉即可（对局仍可正常进行，但人口会逐渐灭绝）。

## 3. 性能设计（重点）

### 3.1 模拟内核

| 设计 | 说明 |
|---|---|
| **SoA 数据布局** | 全部个体状态用列式 TypedArray（`src/core/store.js`），零对象、零 GC 压力 |
| **热循环独立模块** | 对战结算在 `src/core/battle.js`，零分配、零闭包，V8 全内联；拆分小函数 + 预查表避免 deopt |
| **O(n) 配对** | 随机配对用部分 Fisher-Yates（每对 1 次随机数）；相近匹配用计数排序分桶，**不做全量排序** |
| **SharedArrayBuffer 无锁并行** | 对战区间按 pair 切分给 4 个 worker 线程（`src/core/battle-pool.js`），个体每回合只出现在一个 pair 中 → 写入槽位互不相交，无需加锁；主线程用 `Atomics.wait` 同步等待 |
| **自适应快照** | 只有存在观看者时才构建快照；快照间隔按分析耗时自适应（80~600ms） |
| **零拷贝统计** | `src/core/analytics.js` 单次遍历同时产出 128 箱直方图、近似基尼/洛伦兹、阶层、天赋、策略分布、6.5 万采样点 + 192×160 策略网格，全部预分配复用 |
| **可复现** | 全局 xoshiro128** 随机源（`src/core/rng.js`），同 seed 同配置完全可复现（并行模式下同机同 worker 数可复现） |

### 3.2 可视化/传输

- 快照走 **HTTP chunked 二进制流**（`/api/stream`）：帧头 16 字节 + JSON 元数据 + typed-array sections，前端零拷贝解析。
- 密云点：单帧约 2.3MB（6.5 万采样点 + 网格 + 直方图），本地 10Hz 更新毫无压力。
- WebGL2 单次 `drawArrays` 点云 + 单 quad 热图，纹理/缓冲复用（`texSubImage2D`/`bufferSubData`），DOM 更新 rAF 合批 + ≥80ms 节流。
- 慢客户端自动丢帧（写缓冲 > 8MB），不影响模拟线程。

### 3.3 实测性能（本机 16 核 / 64GB / Node 22，Windows）

| 人口 | 初始化 | 每回合 | 模拟速度 | 快照耗时 | 单帧 | 并行线程 | RSS |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 5 万 | 61 ms | **7.5 ms** | **132 回合/秒** | 8.3 ms | 1.78 MB | 4 | 137 MB |
| 20 万 | 87 ms | **19.4 ms** | **51 回合/秒** | 13.5 ms | 2.36 MB | 4 | 184 MB |
| 100 万 | 234 ms | **84.0 ms** | **11.9 回合/秒** | 44.3 ms | 2.36 MB | 4 | 342 MB |

> 100 万人口下每回合 ≈ 50 万局对战结算 + 100 万次年龄/利息/淘汰判定 + 繁殖/统计，
> 即约 **1200 万次个体交互/秒**。可用 `node bench/bench.js --pop 1000000 --rounds 20` 复测；
> `--patch '{"parallel":{"enabled":false}}'` 可对比单线程（100 万约 6~7 回合/秒）。
> 开启公会模式（进阶模式，默认关闭）后 100 万人口约 **7.7 回合/秒**（+45ms/回合：缴金/兜底扫描 + 成本折扣读取）。
> 人口增长到上限（各预设上限见 `config.js` 的 `maxPopulation`）后模拟速度会按人数线性下降。

## 4. 项目结构

```
src/
  index.js              CLI 入口（参数解析、启动服务、优雅退出）
  core/
    config.js           全部参数（默认值/预设/归一化/派生字段）
    rng.js              xoshiro128** 随机源 + 稳定散列泳道
    store.js            AgentStore（SoA TypedArray，SAB 支持）
    engine.js           回合循环：事件→衰老/利息/淘汰→匹配对战→繁殖→汇总
    battle.js           对战热循环（单线程/多线程共用）
    battle-pool.js      并行对战线程池（SharedArrayBuffer + Atomics）
    genetics.js         策略基因：随机/遗传/突变/出拳/三角坐标
    talents.js          天赋：抽签/遗传/效果系数
    events.js           宏观调控 1~4 + 保底 + 瘟疫 + 资源资金池
    families.js         家族命名/创始分配/聚合 TopN
    guilds.js           公会模式：入会/缴金共担/兜底开除/等级/团体战/聚合 TopN
    analytics.js        统计/采样/网格/时间序列/阶层流动（快照数据生产）
    tracking.js         个体追踪（一生资产曲线/谱系）
    snapshot.js         二进制帧装配
  worker/
    sim-worker.js       模拟引擎（独立线程，与 HTTP 解耦）
    battle-worker.js    并行对战 worker（每线程处理一段 pair 区间）
  server/
    server.js           HTTP 服务 + 静态资源 + 二进制流 + 控制 API
web/                    纯原生前端（ESM + WebGL2 + Canvas2D，无构建）
  index.html  css/style.css
  js/{app,protocol,glview,charts,panels,format,mock,selftest}.js
test/                   单元/集成测试（node:test）
bench/                  基准测试 & 调参探索
docs/                   协议、模块契约、UI 规格、规则实现映射
scripts/                检查/探针/冒烟测试/静态服务等工具
```

## 6. 已知限制 / 后续方向

- **家族战争模式**（规则 4.6 的可选玩法）尚未实现（公会模式、阶层流动率已实现）。
- **匹配**：资产相近/策略相近采用分桶近似（O(n)），不是全局最优匹配；分桶参数可在参数面板调整。
- **公会模式性能**：开启后 100 万人口下每回合额外约 +45ms（缴金/兜底/团战扫描 + 成本折扣读取），
  即 100 万约 7.7 回合/秒（关闭时 ~12 回合/秒）；默认关闭，属进阶模式。
- **并行确定性**：并行对战下随机流按 worker 分区，同机同 worker 数可复现；不同机器核心数不同会得到不同轨迹（单线程模式完全确定）。
  在 `node --input-type=module -e` 这类内联脚本中创建引擎时，并行 worker 可能因 execArgv 继承问题启动失败并自动回退单线程。
- 快照分析在 100 万人口下约 36~44ms/帧（含阶层流动统计），因此百万预设的 UI 更新约 3~5 帧/秒（模拟本身不卡顿）；20 万以下可流畅 10Hz+。
- 人口达到预设上限（`maxPopulation`）后停止繁殖，模拟速度随人口线性下降。
- **UI 像素级视觉**无法在无浏览器沙箱中自动截图验收（Edge 内部 IPC 被沙箱拒绝）；
  已用 Node 端 DOM/Canvas/WebGL 桩 + 页面内 `?selftest=1` 断言 + 真实后端端到端联调替代，请用浏览器做最终人工确认。
