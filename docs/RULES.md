# 规则实现映射（RULES）

本文逐条对照《百万猜拳演化模拟器 · 完整规则设计》，说明**每条规则在代码中的实现位置**与**语义取舍**。
标 ⚠ 的条目表示与文档字面存在偏差或做了必要扩展，理由已写明。

---

## 一、核心基础规则

### 1.1 个体定义

| 规则 | 实现 | 位置 |
|---|---|---|
| ID 唯一标识 | 单调递增 `id`（永不复用），跨线程/帧稳定 | `store.js: this.id`, `alloc()` |
| 当前资产（可正可负） | `assets: Float64Array` | `store.js` |
| 累计猜拳次数 / 胜 / 负 / 平 | `stats: Int32Array`（stride 4：rounds,wins,losses,draws） | `store.js` |
| 连胜 / 连败记录 | `winStreak / lossStreak: Int16Array` | `store.js` |
| 年龄（存活轮次） | `age` 每回合 +1，超过 `maxAge`（参数 13）自然死亡 | `engine.js:_individualPhase()` |
| 策略基因 | `gene: Float32Array`（stride 6：石头/剪刀/布概率 + 风险偏好 + 保守阈值 + 激进阈值） | `genetics.js` |
| 状态（正常/破产/已淘汰） | `alive`/`frozen` 位标记；破产即从存活表移除 | `store.js`, `engine.js` |
| ⚠ 额外字段 | 负债上限、成本承受能力、天赋、家族/母系、父母 ID、代数、公会、瘟疫状态、最近对手 | `store.js` |

### 1.2 猜拳匹配机制

| 规则 | 实现 |
|---|---|
| 匹配池 = 存活且未冻结 | `engine.js:_buildPool()`（`alive===1 && frozen===0`）|
| 随机匹配（默认） | 部分 Fisher-Yates：每对只需 1 次随机数，O(n)，`_pairRandom()` |
| 资产相近匹配（±X%） | 按资产对数分桶（`(1+X%)` 为底），桶内相邻配对，奇数余数全局随机配对；`_pairByWealth()` |
| 策略相近匹配 | 策略三角坐标在单纯形上做 2D 分桶（默认 4×4=16 桶），桶内配对；`_pairByStrategy()` |
| ⚠ 相近匹配为分桶近似 | 不是全局最优/最小差匹配（全量排序不可接受）；桶数可配 `matching.strategyBins` |
| 回合概念 | `Engine.tick()` 一次 = 一回合：配对→出拳→结算→繁殖→统一更新状态 |

### 1.3 猜拳结算规则

| 规则 | 实现（`battle.js: processBattleRange`） |
|---|---|
| 平局：双方扣成本，资产不转移 | 成本按 `roundCost × costAffinity` 扣除；`pool.amount`/`destroyed` 记账 |
| 胜负：败方扣成本；胜方扣成本并获得败方赌注 | 胜方净收益 = 赌注 − 成本；成本进系统 |
| 赌注 = 本局成本 × 赌注倍率 | `stake = cost × betMultiplier × 风险偏好 × 阶层倾向 × 阈值调整`（见下） |
| 负债可参与 | 资产允许为负，赌注/成本照扣；负债上限内不淘汰 |
| 风险偏好/保守/激进阈值 | 风险系数基因 [0.2,3.0]；资产低于保守阈值赌注 ×0.5；高于激进阈值 ×1.5 |
| 阶层倾向（4.2） | 底层 ×1.25、中层 ×1.05、上层 ×0.95、顶层 ×0.85（底层更激进） |
| ⚠ 成本去向 | 成本视为系统抽水（`destroyed`）；资源有限模式下进系统资金池（`resourceLimited.taxToPool`） |

### 1.4 破产与淘汰

| 规则 | 实现 |
|---|---|
| 资产 < −最大负债 → 破产淘汰 | `assets < -debtLimit`（负债上限含天赋加成）；`engine.js:_individualPhase` / `battle.js` |
| 破产个体永久移除，负资产系统核销 | `_processDeaths()`：负资产计 `created`（债务豁免），正资产默认核销（`destroyed`） |
| 可选：破产清算分配给最近 N 个对手 | `balance.redistribution.enabled`：按最近 N 个对手均分正资产（`_redistributeEstate()`，默认关闭） |
| ⚠ 自然死亡遗产处理（规则未定义） | 采用**总量守恒**设计：遗产由最多 3 名随机存活者继承（`_distributeEstateToRandomHeirs()`），无存活者才核销——避免人口老龄化期财富凭空蒸发导致的经济崩溃 |

## 二、遗传繁殖系统

| 规则 | 实现 |
|---|---|
| 繁殖条件：存活/资产 > 门槛/年龄 ≥ 最小/一生 ≤ 最大次数 | `engine.js:_reproduce()` 全条件检查 |
| ⚠ 额外条件：每回合繁殖概率 | `genetics.reproChancePerRound`（默认 2%）——否则人口指数爆炸（规则未配置该参数，属必要扩展，可设为 1 关闭节流） |
| 新生初始资产 0 | `genetics.initialAsset = 0` |
| 初始负债上限 = 父母均值 × 变异系数 | `debtLimit = (A+B)/2 × (1 + gauss × debtLimitMutation)` |
| 成本承受能力 = 父母加权平均 | 取父母均值（`costAffinity`）；天赋节俭者再 ×0.9 |
| 策略基因 50% 遗传 + 小概率突变 | `genetics.inheritGenome()`：策略概率取父母均值 + 高斯扰动，风险取均值，阈值取中间值，最后按突变率突变 |
| 初始年龄 0 | `age = 0`，`birthRound = 当前回合` |
| 生育成本 = 基础费 + 父母资产比例 | `baseBirthCost + assets × birthCostRatio`，双方各自支付；生育达人 −30% |
| 支付后跌破负债上限 → 繁殖失败 | 支付前检查，失败跳过本对 |
| 基因维度/遗传方式 | 完全按文档表格：三拳偏好=父母均值±变异、风险=加权平均、保守/激进阈值=中间值、突变率参数 10 |

全部参数（含 UI 可见的扩展参数：人口上限、匹配模式、繁殖概率、天赋权重/效果、学习/模仿/逆反、阶层阈值、瘟疫、资源池、家族数、平衡性、并行线程、快照采样等）定义在
[`src/core/config.js`](../src/core/config.js) 的 `DEFAULT_CONFIG` 中，并带中文注释。

> **默认值口径（第 2 轮调优）**：除需求给定的数值型参数外，部分“社会仿真”默认值按 **1 回合≈1 月、寿命 1000 回合≈83 年** 的社会现实口径做了温和调优：
> 最小繁殖年龄 216（=18 岁成年）、均富 60 回合抽 2%（≈0.4%/年财富税式再分配）、随机灾难改为 300 回合 20% 概率×5% 人口×10% 缩水（黑天鹅）、
> 保底 0.5%×20（更广更小额的低保）。初始资金/猜拳成本/负债上限/寿命/利率（1%/回合≈12.7%/年）与通胀（0.02%/回合，温和）保持不变；
> 随机红利仍是经过平衡设计的货币投放机制（期望 ≈ 对局成本），改动会直接影响人口/繁殖/基尼等长期指标，如需“全民分红”式改造需另行标定。

## 四、补充玩法与机制

### 4.1 策略进化
| 规则 | 实现（`battle.js`） |
|---|---|
| 学习：每失败一定次数微调概率，降低失败选项权重 | 每 `learning.lossTrigger`（默认 3）次连败失败：失败拳种概率 ×(1−adjustStep)，差额按比例分给另外两拳；`adjustStrategy()` |
| 学习能力强天赋加速 | `learnFactor` ×(1+0.5) |
| 模仿：有概率模仿高资产个体策略 | 败者资产 < 胜者 ×1.5 时有 `imitateChance` 概率向对手策略混合 15%；`imitateStrategy()` |
| 逆反：连败达到阈值后策略反转，出最少使用的拳种 | 连败 == `reversalStreak`（默认 8）时，最少使用拳种 +0.2 后重新归一化 |

### 4.2 阶级与分层
| 规则 | 实现 |
|---|---|
| 底层/中层/上层/顶层划分（按初始资金倍数） | `config.js: classOf()` + `_derived.classThresholds` |
| 顶层繁殖成功率更高 | 繁殖成功与资产门槛直接相关（顶层资产高 → 更易满足门槛） |
| 底层猜拳更激进 | 赌注阶层倾向系数（底层 ×1.25 … 顶层 ×0.85） |
| 阶层统计与资产占比 | `analytics.js` 每帧统计（人数/占比/资产占比） |
| ✅ 上下流动率 | 每帧统计（自上一帧以来）：`classes[].flowIn/flowOut` + `json.classFlow = {up,down,stay,total,mobility}`，按 slot + 稳定 ID 校验，新个体/槽位复用不计入；UI 显示上移/下移/流动率 |

### 4.3 通货膨胀
- 每回合 `inflationFactor *= (1 + rate)`（≤ maxFactor），成本 = `roundCost × inflationFactor`；
- `inflation.dynamic=true` 时，总资产超过 `dynamicTarget` 后按比例加速（上限 10 倍）；
- **福利名义值通胀指数化**：随机红利 / 保底补助的金额自动 × 当前通胀因子（`events.js: nominalScale()`），
  保证长期运行时真实购买力不变（否则成本上涨而补贴不变会导致 1300+ 回合后经济二次崩塌）；
- 目的：防止后期数值过大/成本相对无限贬值；UI 实时显示当前成本与通胀因子。

### 4.4 借贷与利息
- 负资产每回合计息：`利息 = -assets × rate`；负债超过 `debtLimit × usuryThreshold` 后利率 × `usuryMultiplier`（默认 2 倍）；
- 利息为系统消耗（`destroyed`）；计息后仍超过负债上限 → 破产。

### 4.5 职业/天赋
- 6 类天赋：无 / 幸运儿 / 节俭者 / 生育达人 / 学习天才 / 负债抗性；
- 效果分别作用于：败方翻盘概率、成本系数、生育成本系数、学习速度、负债上限；
- 出生按权重抽签，后代继承父母之一并可按 `inheritanceMutation` 概率突变；
- 全部权重/效果可配置（`talents.weights / talents.effects`）。

### 4.6 家族谱系
- 每局创建 `families.count`（默认 512）个中文姓氏家族（「赵家」「钱家」…）；
- 初始个体随机分配家族；后代**继承父系家族**、记录母系家族；
- 记录父/母稳定 ID + 槽位提示，`generation` 代数逐代 +1；
- 快照产出：总资产 TopN、人数 TopN、最高代数 TopN 家族榜；
- 个体追踪面板展示追踪个体的家族、代数、父母 ID 与一生资产曲线。
- ⚠ 家族战争模式（可选玩法）未实现。

## 五、进阶游戏模式

| 模式 | 状态 | 说明 |
|---|---|---|
| 5.1 瘟疫 | ✅ 已实现 | 按 `plague.{startRound,everyRounds,probability}` 触发；激活后每回合按 `infectRate` 感染、感染者按 `damagePct` 流失资产；有 `antibodyChance` 概率产生抗体（可遗传）；感染者资产过低时按 `lowWealthExtraDeath` 概率死亡（死亡资产由引擎统一核销） |
| 5.2 资源有限 | ✅ 已实现 | `resourceLimited.{enabled,initialPool,taxToPool,welfareFromPool}`：猜拳成本作为税收进系统资金池，福利/分红从池支取，池空时按比例缩减或跳过 |
| 5.3 组队公会 | ✅ 已实现（默认关闭） | `src/core/guilds.js`：① **加入公会**（建号按 joinChance 随机、后代继承父系公会、每回合按 recruitChance 招收新成员）；② **资产风险共担**（成员每回合缴 `contributeRate` 正资产入金库，濒临破产时金库按 `coverRatio` 兜底，仍超限则**开除**）；③ **等级制度**（金库+成员资产总额决定等级，等级越高成员猜拳成本折扣越大，上限 maxLevel）；④ **公会团体战**（按 `warChance` 触发，双方各抽 `warChampionCount` 名成员用策略基因出拳，赢家金库获得对方下注、记 wins，产出 `guild.war` 事件）；快照输出资产/人数/胜场三类公会榜。UI 提供公会排行面板（参数面板可开启） |

## 七、平衡性补充规则

| 规则 | 实现 |
|---|---|
| 新手保护：新生个体前 K 回合负债达上限不淘汰而冻结 | `balance.newbieProtectRounds`（默认 10）；触发时 `frozen=1` 退出匹配池，保护期结束仍超限则破产 |
| 连胜惩罚：连胜达阈值后胜率略微下降 | `learning.winStreakPenalty`（默认 ≥8 连胜后每局 8% 概率把结果翻转为负） |
| 资产上限软限制：超过极高阈值收益递减 | `balance.assetSoftCap`（超过 10 万后赢家收益 ×0.85，差额核销） |
| 保底机制：每回合随机抽取少量底层个体补助 | `macro.subsidy`（默认每回合给最穷 `countPct=0.5%` 存活人口各 +20，按人口缩放保证不同预设行为一致） |

## 九、与需求文档的偏差清单（汇总）

1. **经济默认通缩**：按规则字面（成本是系统抽水、赌注个体间转移）胜方净收益≈0，系统会持续通缩、繁殖门槛不可达。
   默认开启「随机红利」（每 2 回合 50% 概率 × 30% 个体 × 140 元、名义值通胀指数化，期望收入≈10.5/人/回合 ≈ 覆盖对局成本）
   作为货币投放；自然死亡遗产由随机存活者继承（不蒸发）。关闭分红即得到纯通缩经济。
2. **繁殖节流参数** `reproChancePerRound` 为新增参数（防止指数爆炸）。
3. **相近匹配**为分桶近似，非全局最优匹配。
4. **基尼系数**为直方图近似值（百万级全量排序性能不可接受）。
5. **家族战争模式**（规则 4.6 的可选玩法）未实现；公会模式、阶层流动率已在第 2 轮补齐。
6. **破产清算**（分给最近 N 个对手）默认关闭，需在参数中开启；自然死亡遗产默认由随机存活者继承（守恒设计，规则未定义）。
7. **并行模式随机流**按 worker 分区（同机可复现），与单线程轨迹不同；单线程模式完全确定。
   若在 `node --input-type=module -e` 这类内联脚本中创建引擎，并行 worker 可能因 execArgv 继承问题启动失败并自动回退单线程（引擎/主程序不受影响）。
8. **UI 像素级验收**在无浏览器环境中无法自动完成，提供 `?mock=1` 演示模式与 `?selftest=1` 页面内自检（21 项）。
